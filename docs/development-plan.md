# 中国开源地图研发计划

版本：v0.8 ｜ 日期：2026-10-28 ｜ 依据：[PRD v0.10](PRD.md)

本文仅本地保存，不纳入 Git、提交或 PR。调整后的主线为自动化数据与机器可读性优先，问答和完整 UI 自适应回归后置。任务依据源码核查及官方搜索项目资料制定，尚未实施或验收；本次不运行采集、部署服务或变更外部配置。

已确认的技术边界：首阶段仅 GitHub Pages；条目及采集数据以 YAML 维护，构建生成公开页面、数据与搜索资源；搜索在浏览器运行，优先复用 MiniSearch。后续独立部署仍优先复用静态产物，按需新增的服务单独评审。

## 1. 目标与排期假设

核心交付是“自动发现／更新 → 去重补充 → 白名单指标自动更新／事实候选审核 → 统一公开 → 人类检索与机器读取”。网站默认 Landscape；问答已确认 B 方案和路线 2，默认悬浮框、展开后分栏，延至 P3。用户填写模型与 Token 并保存在浏览器，浏览器直连用户确认的模型端点，平台只提供分析框架。

- 人员：沿用 1 名研发全职，内容审核、三语校对、验收与发布人员兼职，具体人员在 S0 确认。
- 首发范围：离线／CI 中的 GitHub／Gitee 采集、候选发现、YAML 更新与失败保护、无 JS 可读页面与机器数据、纯静态搜索、三语及基本纠错，生成 Pages 可托管的完整静态包。
- 工期暂沿用 **22–33 个工作日**，含约 20% 缓冲建议 **27–40 个工作日，约 6–8 个工作周**。移除独立搜索服务接入与运维任务后，仍保留三语检索、YAML 流水线及 Pages 适配验证，S0 实测后再校准；阶段 3／4 的体验、自助和问答不在此范围。
- 假设：复用现有 Rust／Node／SolidJS 和浏览器 MiniSearch，来源范围可配置，先支持审核名单和指定组织／目录，不以全网无边界抓取作为首发目标；内容及时反馈，首发无需数据库或常驻应用／搜索后端。
- 从实际开工日计算，S0 后按冷构建、API、托管和搜索验证情况校准。第三方审批、预算和人员等待另计；不因延后 UI 测试而省略数据正确性、发布过滤及故障回退验证。

## 3. 首发阶段与里程碑

| 阶段 | 优先级 | 预计工作日 | 主要交付与退出条件 |

主线为 **S0 → S1 → S2 → S3 → S4**，全部属于 GitHub Pages 首发。采集在离线／CI 环境先生成有效 YAML，机器页面和浏览器搜索再消费同一版本公开投影；不把一名研发的开发任务按并行压缩工期。搜索最小验证可在 S0 提前暴露问题，完善在 S3；内容复核和翻译人员可持续并行准备。

实现边界：不能通过整体关闭 `site-profile` 恢复旧采集，否则会连带启用商业数据／治理采集和额外产物；当前旧 GitHub 缓存也不能直接保证失败留旧值。自动化应独立输出本站候选和快照 YAML，构建只消费有效版本；Pages 只托管生成文件，采集凭证不进入浏览器。不引入常驻采集服务、搜索实例、数据库或为未来能力预建后端；现有非内容配置和素材格式不为统一 YAML 而重写。

Issue → PR 自动化的安全边界：Action 只消费 Issue Form 的结构化字段，不把 Issue 文本当作 shell 命令或代码执行；使用最小的 `issues`、`contents` 和 `pull-requests` 权限；分支与 PR 创建必须幂等并保留原 Issue 链接。Action 只能生成草稿或待审记录，不能把 `in_review` 改成 `published`，不能自动合并；最终发布仍要求内容审核者核对外部证据，并由站点负责人批准。审核人和必需审查规则需在实现阶段补充 CODEOWNERS 或分支保护配置。

## 5. 首发验收与交付

优先验收数据和机器使用，UI 全量自适应测试不是前期门禁：

- **采集与发现：** 已收录更新、新候选、缺字段、改名／迁仓及重复运行均有样例；不重复建档，不将未知字段当零值，不因 API 异常判定归档。
- **失败与新鲜度：** 覆盖限流、分页、部分成功、源不可用、无 Release 和任务重试；保留旧有效数据与时间标记，定时失败不影响已发布网站。
- **审核边界：** 只有批准的白名单指标自动更新；新收录和起源、许可、归属、治理、维护状态等事实须审核。候选与内部记录不进入任何公开页面、机器数据或索引。
- **Issue → PR：** 新增、纠错、Logo 替换和撤回 Issue 能生成一条可追踪的 Draft PR；重复事件不会重复建 PR，异常字段不会执行命令或改写其他文件；PR 默认保持 `in_review`，未获得人工批准不会进入公开投影。
- **人工审核闸门：** PR 必须包含原 Issue、证据链接和变更摘要；CI 失败不能合并；内容审核者核对起源、许可证范围、当前归属、文案和素材来源，站点负责人批准后才允许改为 `published` 并合并。
- **机器访问：** 普通 HTTP 和禁用 JS 都能读到正文、日期与证据；从首页／目录发现条目，三语 canonical／语言关联、sitemap、Markdown／JSON 互相一致，撤回退出可发现列表。
- **检索与使用：** 不访问外部搜索 API即可完成浏览器查询；三语、别名、筛选、去重及重建后的更新删除通过样例，命中总数不等于下拉展示上限。验证首次加载、版本错配及失败重试；Landscape、目录与详情／纠错可操作，基本键盘流程不失效，不提前执行完整断点／视觉矩阵。
- **YAML 与发布：** 正式条目、采集配置和有效快照由对应 YAML 维护，HTML、公开 JSON、Markdown、搜索资源及 sitemap 从同版公开投影生成；校验 Pages 子路径和缓存版本，错配时提示重新加载。完整包失败保护和重新发布旧产物的回滚可重复，不能用 SPA 404 入口代替真实详情正文。

按变更运行已有 Rust／前端相关测试、lint、内容校验、完整构建、站点输出测试与 release 检查；新增验证聚焦采集恢复、YAML 派生一致性、公开过滤、机器访问及静态搜索加载。命令参考[内容维护](content-maintenance.md)、[候选包验收](release-candidate.md)和[部署回滚](deployment-runbook.md)，具体以仓库配置及 CI 为准；涉及服务器的可选部署步骤不作为 Pages 首发要求。

记录固定设备与网络下的加载、检索耗时和数据规模，在 S0 确认性能目标；任务完成、内容审核、DCO 提交确认及生产发布分别处理。计划不自动授权付费实例、外部权限或生产定时任务配置。

| F6-1：本地配置 | 提供 API Base URL、模型 ID、Token 输入；点击保存写入当前站点 localStorage，刷新恢复；可仅在内存中使用；遮罩、修改、切换域名重填及一键清除有效，无账号同步 | F5 及协议适配范围确认 |
| F6-2：模型直连 | 浏览器检索公开资料后组装上下文，由用户主动发送到其确认的端点；支持连接测试、取消与安全渲染；无配置或调用失败保留检索，不自动代理或换模型重试 | F6-1 |
| F6-3：兼容与回归 | 模拟接口或测试者自带配置验证保存／刷新、仅会话模式、清除后旧 Token 不再使用、域名切换、鉴权／模型／限流／超时／断网／CORS 错误；检查请求与日志不向本站、埋点或默认导出泄露 Token，并以约 100 题样例检查引用和资料不足处理 | F6-1、F6-2 |

本地保存不作为加密或绝对安全承诺，按 PRD 第 5.2 节提示同源脚本与可信设备边界。调用时 Token、问题和公开上下文会发往用户确认的模型端点，界面需显示接收方和计费归属。平台不收集用户 Token、不购买统一推理额度，不再以平台 Serverless、预设模型分流及问答 API 月费上限为 F6 前提。

用户问答费用由用户账号与提供方结算；平台仅估算框架、适配器和评测维护成本。此方案不复用用户 Token 执行 P0 定时采集或站点搜索；采集任务、静态构建、托管及流量按实际额度核验，首发无独立搜索实例费用。F6 仍属 P3，首发暂沿用 22–33 日、含缓冲 27–40 日，按 S0 实测校准。

## 7. 纯静态搜索选型与验证

2026-10-28 按已确认托管条件收敛：只评估资源可随 Pages 发布、浏览器内查询的开源方案。Meilisearch 和 Typesense 移出本轮候选；不采购搜索实例、不接入托管搜索 API。选型以项目适用性和验证结果为准，不以 stars 或“最新”替代需求验收。

| 方案 | 已核实基础／运行形态 | 本项目安排 |
| --- | --- | --- |
| [MiniSearch](https://github.com/lucaong/minisearch) | 项目依赖声明 `^7.2.0`、锁文件为 `7.2.0`，MIT；源码已在浏览器建立内存索引，无需搜索服务器 | 首发优先复用；完善三语、筛选与加载状态，通过样例即可沿用 |
| [ZBSearch 浏览器本地方案](https://github.com/micheleriva/zbsearch) | README 提供浏览器模块用法，仓库许可证为 Apache-2.0；仅评估本地全文检索与筛选，资源随站发布，无需搜索服务器；具体发布版本、中文处理及体积在启用评估时核验 | 仅在 MiniSearch 无法满足目标时作为唯一备选，不要求首发同时接入或维护 |

核验依据为 [搜索实现](../ui/webapp/src/utils/search.ts)、[前端依赖](../ui/webapp/package.json)及[锁文件](../ui/webapp/yarn.lock)。当前实现通过 `addAllAsync` 在浏览器建索引，已处理别名、字段权重和前缀，尚不能据此认定中文片段、简繁等价及组合筛选均已达标，也未核实线上站点是否发布这份实现。

ZBSearch 的运行方式与许可于 2026-10-28 核对其官方 [README](https://github.com/micheleriva/zbsearch/blob/main/README.md) 和 [LICENSE.md](https://github.com/micheleriva/zbsearch/blob/main/LICENSE.md)。本次仅更新备选安排，未接入该依赖或验证搜索效果；S3 如需启用评估，再锁定具体发布版本与对应许可证，按同一组样例检验。

S3 验证清单：

1. **内容与效果：** 简繁英文名称、中文片段、混合词、别名及多条件筛选；稳定 ID 去重，命中总数与截断展示分开，更新／撤回经 YAML 重建后生效。
2. **纯静态链路：** 只消费同版公开搜索文档／索引，不泄露待审记录；校验 Pages 子路径、首次加载、初始化、缓存错配和失败提示，加载失败仍有目录／详情入口。
3. **规模与维护：** 固定数据规模记录包／索引体积、初始化时间、查询耗时和内存，目标在 S0 冻结。优先沿用现有浏览器建索引，仅有实测需要时预生成索引或启用备选，避免提前建设双引擎。

公开 HTML 正文满足无 JS 抓取，交互搜索由浏览器 JavaScript 完成，两者分别验收。后续迁到独立静态托管仍使用此模式；增加服务必须另有明确需求与资源评审。
