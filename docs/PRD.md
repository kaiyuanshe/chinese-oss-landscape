## 1. 项目背景与目标

基于 CNCF Landscape2 建设由开源社维护的中国开源条目发现网站。最核心的能力是持续自动化收集、补充和更新可信数据；默认以 Landscape 展示，兼顾人类浏览、大模型读取和爬虫发现。保留极简、生动、高互动、高自助的目标，问答作为后续辅助能力。

| 用户 | 核心任务 |
| --- | --- |
| 普通访客、开发者及选型人员 | 按领域或关键词找条目，查看许可、来源与维护状态 |
| 项目或社区维护者 | 分享条目链接，提出新增、资料补充与纠错建议 |
| 内容编辑与审核人员 | 核验自动发现与补充的候选资料，处理事实变化和收录审核 |
| 爬虫、大模型与数据使用者 | 无需执行页面脚本即可发现、读取和引用公开条目及其来源 |

数据核心闭环：**自动采集／发现 → 规范化与去重 → 自动更新白名单指标／提交事实候选 → 审核 → 统一生成公开页面、数据及搜索索引**。访客侧继续完成地图发现、详情阅读、原始来源访问与纠错。

现有基础：目录有 31 条已发布记录（29 个软件、1 个模型权重、1 个社区）；已有中英文、地图、搜索、详情和公开投影。本站构建默认关闭外部采集，尚无本站候选发现与快照流水线；页面正文依赖客户端，已有站点级元信息不能代替条目可抓取正文。繁体、自动化链路及机器可读页面均需补齐。以上不代表已验收或生产上线，31 条也不是完整生态名录。

## 2. 设计方案

### 2.1 首发已确认功能

| 功能 | 首发要求 |
| --- | --- |
| 自动化数据（P0） | 更新已收录条目、发现新候选并补充缺失资料；来源、采集时间、审核边界、增量与失败保护明确 |
| 机器可读（P0） | 首页、目录、条目及关于信息可通过普通 HTTP 读取正文；公开 HTML、JSON、Markdown、站点地图与数据说明保持一致 |
| 首页与地图 | 默认 Landscape，保留开源社品牌、搜索入口和分类网格；复用现有移动卡片，基础操作可用 |
| 搜索与筛选 | 仅采用可随 GitHub Pages 发布的纯静态方案，优先复用 MiniSearch；支持三语名称、关键词及别名与组合筛选，见第 6.2 节 |
| 条目详情 | 地图内沿用弹窗，同时提供稳定静态详情链接；展示原始名称、简介、类型、入口、许可、起源、归属、维护状态、证据及核验日期 |
| 三语体验 | 简体中文、共用繁体中文、English 三态切换，默认简体；核心界面和分类标签三语齐全，专有名称保留原文 |
| 稳定链接 | 条目可分享和直接访问；保留分类、筛选、语言等 URL 状态，切换语言不丢失当前条目或筛选 |
| 补充与纠错 | 条目内提供 GitHub Issue 入口，使用新增、纠错、Logo 替换、撤回模板；资料修改通过 PR 审核发布 |
| 关于与说明 | 公开收录口径、来源声明、内容更新时间和运营入口，说明收录不代表认证或质量背书 |

简介优先展示所选语言；缺少译文时回退简体并提示。繁体文案须校对，不能仅以机械转换完成验收。名称、网址和来源引文保留原文。现有 Issue 模板为英文，首发需补齐三语提交指引及可填写的字段说明，提交仍跳转 GitHub。

### 2.2 已选首页与问答形态（P3，延后）

已选择 B：对话与地图协同。默认首页始终为 Landscape；问答功能上线后默认呈现轻量悬浮框，用户展开时形成问答面板＋地图分栏，收起后回到悬浮状态，保留地图浏览状态。问答与完整交互实现后置到阶段 4，首发不要求先交付机器人或悬浮窗口；A／C 不再是待选方案。

### 2.3 后续条目模板与来源徽章

阶段 3A 扩展核心成员、治理机制、商业化进程、时间线及相关项目，认领入口随阶段 3B 上线；保留首发的简介、起源、归属、许可、维护状态与来源。扩展信息逐项附公开证据及日期，有资料再展示，缺失不阻塞首发，也不推断未公开事实。

来源徽章区分“官方公开来源”“维护者提供（未经第三方核验）”“社区补充（审核后显示）”。徽章描述来源渠道与核验程度，不能替代审核状态或暗示第三方认证。验收时能从徽章查看对应证据，未经审核的投稿不公开。

### 2.4 首发核心流程与验收

以下为首发验收要求，不是本轮已通过的测试结论。P0 优先验收自动化数据与机器访问，用户流程保留基本冒烟，完整 UI 自适应矩阵后置。

1. **自动化收集：** 覆盖已收录更新、新候选发现、缺失资料补充、去重、人工审核及重跑；限流或部分失败保留有效数据，未审核候选不公开。
2. **机器访问：** 禁用 JavaScript 或直接请求页面可读正文、证据与日期；从公开目录能逐链接发现条目，HTML、JSON、Markdown、sitemap 和索引使用同版公开数据。
3. **搜索与浏览：** 浏览器直接查询随站发布的公开数据，无搜索后端；简繁英文、别名、组合筛选、清空与零结果提示正常，命中总数与展示数量分开，跨分类不重复计数。索引加载失败或版本不符时提示重试，目录、地图与详情仍可访问。
4. **详情与链接：** 详情信息完整、原始入口可访问；静态链接可直达，旧 ID 可解析；撤回说明、替代条目与真实不存在资源的行为明确。
5. **语言与状态：** 默认简体，URL 语言优先于偏好；三语切换保留条目与筛选，译文缺失提示回退，原始名称保持原文。
6. **审核与纠错：** Issue 携带条目身份；草稿、待审及内部信息不进入任何公开页面、数据或索引；待复核有提示，撤回退出列表和检索。
7. **前期 UI 冒烟：** 默认 Landscape、搜索、详情与纠错入口可操作，主要键盘操作不失效。390 px／1440 px、更多断点与完整视觉／自适应回归放到阶段 3A，不作为前期重点工作包。

## 3. 数据与内容

### 3.1 稳定事实与审核

- 沿用 `site/catalog.yml` 作为正式条目内容唯一来源，配置与介绍沿用现有相关 YAML。新增采集配置、候选资料及需持久保留的指标快照也以 YAML 维护，具体拆分在 S0 确认；原始响应、临时缓存不作为权威内容源。HTML、公开 JSON、Markdown 和搜索文档／索引均由构建生成，不手工维护第二套内容数据。条目使用稳定 ID，名称、分类和语言变化不改变身份；Logo 本地保存并记录来源。
- 收录对象包括软件、模型权重、数据集、开放标准、社区／组织。总量称“收录条目”，分类计数不将组织等同于软件项目；不为凑齐类型降低门槛。
- 中国起源须有公开证据，分别记录大陆、香港、澳门、台湾；历史起源与当前归属分开。符合起源条件的条目迁移海外后仍可收录。
- 按实际资产核验资格：软件核验公开源码与 OSI 开源许可证；权重、数据核验各自许可；开放标准分别核验正文许可与实施／专利政策；社区核验官方身份与活动。许可、实施政策或获取条件未决时保留待审，不能借用关联代码许可证推定合格。
- 发布状态与维护状态分开。新条目遵循 `draft → in_review → published`；已发布条目可标为待复核 `needs_review` 或撤回 `withdrawn`。维护状态使用活跃、归档、未知，网络超时不能直接判定归档。
- 公开事实须有证据与核验日期；无法确认时标注未知。内容负责人批准新增和撤回，技术校验不代替内容审核；动态指标不得覆盖已审核的起源、许可或归属结论。

### 3.2 自动化收集与补充（P0 核心）

采集作为离线脚本或 GitHub Actions 任务，独立于网站构建，支持定时与手动运行；默认每日增量、每周汇总“本周变化”，频率可按 API 额度调整。采集结果形成 YAML 更新，按既定校验／审核规则纳入有效数据版本后再构建发布；访客访问时不触发采集，也不需要常驻采集后端。核心包含两条链路：

- **已收录更新：** 从已确认的官方入口采集 Star、仓库活动指标、最新正式版本等白名单指标，生成版本化快照；公开值附来源、采集时间、最近成功时间和状态，不以空值或失败覆盖有效旧值。
- **新候选与补充：** 从配置的 GitHub／Gitee 官方组织、仓库目录及允许来源发现候选，按平台仓库身份、稳定 ID、别名及迁仓关联去重；自动整理简介、入口和资格证据等缺失资料，形成待审记录或 PR。缺失字段保持未知，新候选不自动认定起源或资格。

`site/catalog.yml` 仍是身份、事实与审核的唯一权威来源；候选与动态快照按稳定 ID 关联。已审核来源的白名单指标可按规则自动更新；简介、起源、许可、归属、治理、人员与人工维护状态的变化先提示审核，批准后更新目录。“活跃度”仅指活动指标，不自动改写条目维护状态。

### 3.3 可靠性与公开更新

支持分页、增量、幂等、限流退避与部分成功合并；重复任务不重复创建候选，改名／迁仓先复核关联。无 Release、未知字段、权限不足与暂时失败分别记录；失败保留上次有效 YAML／快照，不仅依赖可能失效的 CI 缓存，显示过期状态，无变化不伪造汇总。

仅使用官方 API 或明确允许的来源，不抓取 Crunchbase、PitchBook、ITJuzi 等商业站点。凭证仅在采集环境使用；候选日志和公开数据不得包含凭证。API 条款与额度在 P0 阶段确认。更新通过校验后统一生成地图、静态正文、公开数据和搜索索引；失败保留上一完整版本，采集故障不阻断访客读取已发布内容。

具体贡献与审核操作见[内容维护说明](content-maintenance.md)。

## 4. 自助补充与认领

首发继续使用条目级 GitHub Issue 与数据 PR，自动候选也进入现有内容审核流程。阶段 3B 保留以下站内自助目标：

- **维护者认领：** 通过 GitHub 或 Gitee 验证仓库管理员或组织成员身份，由审核人员确认条目关联和可维护范围；认领不等于自动发布或获得仓库写权限。
- **结构化表单：** 填写核心成员、治理、商业化等资料，每项附证据链接和日期；条目内可直接纠错，无需进入 GitHub 填写 Issue，身份验证可跳转授权页。
- **审核队列：** 认领资料和社区补充均先进入审核，支持补证、退回、批准及撤回；批准内容回写唯一内容源后发布，避免站内资料与目录形成两套事实。
- **申诉：** 提供认领争议、审核结果异议及纠错申诉入口；审核人员名单、验证细则、处理责任与申诉机制须在该阶段启动前确定。

该阶段验收覆盖身份不符、重复认领、证据不足、审核退回与通过、站内纠错及申诉；未经批准的内容不得出现在公开页面。涉及身份验证、资料接收或审核服务的能力须在该阶段单独确认必要性、部署与维护资源，未确认前沿用 Issue／PR；不为预留这些能力提前搭建后端。它们不构成纯静态首发、独立静态托管或浏览器 BYOK 问答的前置条件。

## 5. 问答机器人

### 5.1 用户自备模型，站点提供分析框架

**已确认采用路线 2：浏览器直连用户模型（BYOK）。** 问答仍为 P3，阶段 4 交付 B 方案与默认悬浮框。站点负责检索公开资料、组装分析上下文、接口适配、回答展示及引用；用户自行选择模型、填写 Token 并承担提供方计费。打开悬浮框不自动发起模型请求，未配置模型也可使用基础检索。

| 路线 | 能力与边界 | 基本验收 |
| --- | --- | --- |
| 路线 2：浏览器直连用户模型（BYOK，已确认） | 浏览器获取公开检索结果，组装问题与上下文，直接调用用户确认的模型端点；配置有效且用户主动发送时启用 | 自定义模型可调用，引用与陈述对应；本地配置、请求目标及错误回退符合第 5.2、5.3 节 |

检索保留为路线 2 的上下文准备，以及未配置模型或调用失败时的回退能力；不再安排独立的路线 1 问答交付阶段。

取消固定模型供应商、Haiku／Sonnet／Opus 分档及平台自动选模。通过可扩展适配器支持明确列出的接口协议，用户可手填 API Base URL、模型 ID 和 API Token，不依赖提供方必须开放模型列表接口；具体兼容协议范围在阶段 4 冻结，不承诺任意端点均能浏览器直连。

### 5.2 浏览器本地配置与请求流向

- **配置与保存：** 用户点击保存后，将接口地址、模型 ID 和 Token 存入当前站点的浏览器 `localStorage`，刷新后可恢复；可选择仅本次会话使用，Token 只留内存。本站不提供账号云同步，Token 遮罩显示，支持修改及一键清除。
- **明确接收方：** Token 不上传本站服务端；仅在用户发起调用时随鉴权请求发送给其确认的模型端点。问题与检索到的公开上下文也发送至该端点，界面显示目标提供方／域名。切换目标域名后要求重新填写 Token。
- **使用边界：** 本地存储不等于加密保险箱，同源脚本可读取；保存界面提示使用可信设备。Token 不进入 URL、日志、埋点、默认配置导出、公开数据或仓库，生成内容按不可信文本安全渲染。
- **清除行为：** 清除时删除本地及内存配置，取消当前请求，后续调用不得继续使用旧 Token。该配置仅用于访客问答，不供后台定时采集或站点搜索服务复用。

### 5.3 回答、兼容性与验收

模型直连受提供方协议、浏览器跨域策略及端点权限约束。鉴权失败、模型不存在、限流、超时、取消、断网或 CORS 不兼容时，显示可操作提示并保留检索结果；可提示配置兼容端点或用户自建端点，不自动经本站或公共代理转发 Token，也不自动换模型重试。

路线 2 的回答与回退检索结果均须附条目链接、显示“数据更新于”日期，事实依据仅来自已收录且已发布资料，超出资料说明不足。保留约 100 个简繁英文真实问题，覆盖找项目、对比、查治理及引用正确性；评测使用模拟接口或测试者自己的配置，不使用平台共享生产 Token。

验收还须覆盖保存／刷新恢复、仅会话模式、切换端点重填、一键清除、无 Token 检索、连接测试与主动调用及上述故障回退；通过请求与日志检查确认 Token 只发往用户确认的模型端点，本站不接收。提供方返回用量时可展示，实际费用由用户账户与提供方结算，不承诺统一费用上限。

## 6. 技术架构、机器可读与搜索

### 6.1 整站对大模型与爬虫友好（P0）

保持默认 Landscape 交互，从同一公开投影生成无 JavaScript 也可读的首页内容、分类／类型目录、条目静态 HTML 和关于页，使用真实链接互相发现。条目 URL 以稳定 ID 标识，三语采用可独立获取的页面路径，正文保留证据、核验日期、采集时间及维护状态。

生成 sitemap、canonical、语言关联及与正文一致的结构化数据，按软件、模型、组织等实际类型表达；避免将搜索与筛选参数组合无限索引。生产环境允许公开内容抓取，本地及预发布继续 noindex；S0 核验 GitHub Pages 项目子路径、语言路径和资源地址。robots.txt 的有效位置在域名根路径，项目子路径内同名文件不能替代根路径规则，须按实际可控范围配置并记录限制。

提供公开 JSON、条目 Markdown、数据格式说明和 llms.txt 发现入口；llms.txt 作为辅助说明，不承诺模型必然收录或排名。所有输出、索引与 sitemap 复用公开过滤，草稿、待审及内部信息不泄露；撤回记录退出列表和索引，旧 ID 输出兼容静态页，撤回链接保留最小说明或替代入口。详情直达依靠实际生成的 HTML 文件，不能仅依赖 SPA 的 404 回退；未知路径和跳转按 Pages 实际能力验收，不以服务端路由重写或自定义状态码为前提。

### 6.2 纯静态搜索，优先复用 MiniSearch（P1）

**选型硬约束是浏览器内查询、资源随站发布、无需搜索后端或第三方查询 API。** 当前源码已集成 MiniSearch，在浏览器读取公开条目并建立内存索引，无需独立部署搜索服务；这说明源码已有能力，不代表已核验线上部署。首发优先复用和完善此方案，依据三语效果与数据规模选择合适版本，不因版本更新或关注度强制换引擎。

仅在 MiniSearch 经必要配置后仍不能满足样例或性能目标时，才评估 [ZBSearch](https://github.com/micheleriva/zbsearch) 的浏览器本地全文检索方案这一备选。已核对其 README 的浏览器运行示例与 Apache-2.0 许可证；接入前仍需锁定发布版本，实测中文处理、简繁检索、组合筛选与包体积，所需资源随站发布。Meilisearch、Typesense 等需要独立搜索服务的方案移出本轮候选，不安排多引擎长期并存。

搜索消费 YAML 构建生成的公开文档；首发可沿用浏览器建索引，是否改为构建时预生成索引由加载与初始化实测决定。页面、文档／索引与版本标识随同一静态包发布，新增、更新和撤回通过更新 YAML 后重建生效。验证简繁英文、中文片段、别名、组合筛选、去重计数和版本错配；中文分词、简繁归一化均需样例验收，不能当作现有已完成能力。加载失败时提供重试和目录入口，不额外引入第二个搜索服务；纯静态不等于首次访问即可离线使用。

### 6.3 构建、托管与范围边界

**首阶段仅托管在 GitHub Pages**，覆盖本文首发的阶段 0–2／研发 S0–S4。沿用现有构建链路，由 YAML 内容及配置生成 HTML、公开数据、搜索资源和素材，作为完整静态包发布；浏览、检索和详情不需要数据库、常驻应用服务或实时第三方 API，不保证外部官网或仓库始终可达。域名沿用或另购仍待定，Pages 的托管选择已确定。

自动采集在本地或 GitHub Actions 定时／手动任务中运行，按每日增量、每周汇总设计，凭证仅供任务环境使用，启用前核验账户额度。有效 YAML 版本经校验／审核后重新构建站点；发布失败保留上一可用版本，回滚采用重新发布已保存的完整稳定产物，不依赖服务器目录切换。

后续按需求逐步迁到独立静态托管，优先复用同一静态包、YAML 数据和稳定链接；独立部署不自动要求引入后端。只有经确认确实需要服务的自助能力才单独增加最小服务，并保持公开浏览与搜索可独立静态运行。路线 2 的浏览器 BYOK 问答同样可作为静态前端扩展，受模型端点跨域能力限制，不以前述服务或托管迁移为前提。

首发不做账号体系、代码托管、项目评分、对比工作台、站内后台、实时第三方指标保证、融资分析、图片导出、完整自适应改版或问答窗口。不为首发重写框架或移除 Rust。公开 JSON／Markdown 供机器读取属于 P0，访客下载 UI、嵌入等仍为后续能力；第 4、5 节和扩展条目资料保留在后续路线。

部署验收与版本回滚引用[候选版本验收](release-candidate.md)和[部署与回滚说明](deployment-runbook.md)；文档更新及验收通过均不等于生产发布授权。

## 7. 预算假设

平台预算用于静态站点、离线采集、构建及数据留存；首发搜索没有独立实例费用。用户问答调用以其自备 Token 向模型提供方结算。以下为待核验项目，不是报价或付费配置授权：

| 项目 | 当前口径 | 使用前需确认 |
| --- | --- | --- |
| 自动化与静态构建成本 | 尚无核准金额；浏览器搜索不采购独立服务 | Actions 任务／构建额度、缓存与有效 YAML／产物留存、包体积和流量 |
| 固定成本 | 草稿按域名每年数十至百元、公开仓库 Pages／Actions 免费额度估算 | 域名实际报价、账户资格、额度及超额计费 |
| 用户模型调用 | 用户自行选择模型、提供 Token 并承担费用；平台不提供共享额度或充值服务 | 界面说明请求目标、计费归属和可能产生费用；提供方限额由用户自行管理 |
| 问答框架维护 | 平台承担前端框架、适配器、兼容性测试及评测维护 | 按阶段 4 的实现范围估算研发和维护投入 |

原草稿按 UV 测算的平台问答月费和 US$100／月上限不再作为当前方案预算。平台无需为访客问答选择统一模型或采购推理额度；采集、构建、托管与流量仍需核验额度和成本。后续独立托管或可选自助服务另行估算，不计入首发固定支出。上线后首月复盘框架兼容性与平台实际运行成本。
